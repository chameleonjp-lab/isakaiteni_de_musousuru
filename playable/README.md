# 王都からの脱出　ブラウザ版

玉座の間から始まる探索ゲーム。謁見が終わると、左下のスティックまたは矢印キーで自由に歩ける。画面をドラッグすると視点が変わる。行き先の札がある廊下を歩いて隣室に入り、「調べる」で人物や仕掛けに関わる。首輪を外したあと、一度も発見されずに境石を内側から外の草地まで歩いて越えると、脱出に成功する。

最短20行程と任意300場面の本文は、[シナリオ資料](../docs/scenario/README.md)と同じJSONから組み込む。プレイヤーの選択と手帳を使って成立を判定し、任意場面は条件を満たしたときに現れる。分岐の両方を見るには、選ぶ前から別の周回で試す場面がある。

[試遊版](https://drive.google.com/file/d/1MZAaQGoNirY7m5cFIuL5zkXc1f0TJIyn/view)と同様に、移動と視点操作を同時に使える。探索中の位置、視点の向き、音設定は進行と一緒に保存する。3D表示を利用できない場合は、文章の選択肢で移動と脱出を進められる。

## HTMLを作る

リポジトリのルートで実行する。

```sh
python -B playable/build.py /tmp/castle_escape.html
node playable/verify.cjs
python -B scripts/verify_scenario.py
```

ビルドは試遊版と同じThree.js r128を読み込み、固定したハッシュと照合する。手元に同じThree.jsファイルがある場合は、ビルドに `--three` とファイルの場所を指定できる。完成したHTMLにはシナリオ、3D用コード、表示、効果音が入る。ブラウザで開くと、一つのファイルで遊べる。ゲームの途中経過は保存を許可するブラウザでは端末に残る。

任意場面や部屋を追加するときは、シナリオ資料のデータを編集してから再ビルドする。本文と条件は原本を基準にし、各仕掛けで表示する複数の選択肢は `puzzles.js` で管理する。

## 3D演出の確認

プレイ版と統合確認版は `playable/stages/` の3段階の演出とモデルを共有する。プレイ版の「手元」で視点を切り替える。無音祈祷室では「扉手元」で開閉中の取っ手を追う。必須行程の結果を読み終えて「続ける」を押すと演出が始まる。境石では、外の草地に着いた時点でゲーム本体に脱出結果を記録する。3D表示を利用できないブラウザーでは、従来の文章と選択肢で進められる。

```sh
python -B playable/build.py /tmp/castle_escape_scene_check.html --scenes
node playable/stages/verify.cjs /path/to/three.min.js
```

統合確認版の「通し確認」では C01 からの新規開始と W04 からの後半確認を選べる。W04 では本体と同じ判定で M01〜M15 を済ませた状態から始まる。「演出見本」に切り替えると、全22場面の47見本を自由に再生できる。統合確認版の進行記録はプレイ版とは別に端末へ保存する。

提出前に、ゲーム本体の全20行程と任意300場面・84選択値を自動検証した。3Dモデルの検証では全22場面・47見本、石段8段の上面、南門の礼の分岐、未開封の4品、境石での成功・失敗・復元、50回の場面切り替えを確認した。iPhone 17 Pro Safariでの描画とタッチ操作は実機確認を要する。

## GitHub Pagesで公開する

GitHub Actionsの「Castle release」は、プレイ用HTMLを作り、シナリオ、3D演出、ブラウザー操作を検証する。ブラウザー検証では、縦402×700と横700×402相当で開始、回転、スティックでの隣室への移動、旧セーブの再開、発見後の死に戻り、歩いての脱出を試す。3Dが使えない場合も文章で最後まで進めるかを確認する。成功した実行の「castle-escape-html」から、確認に使ったHTMLを取得できる。

初回公開前は、iPhone 17 Pro Safariの縦・横でボタン切れ、視点切り替え、セーブの再開を確認する。公開する版の進行不能、誤クリア、セーブ破損、必須ボタンの操作不能を解消してから次に進む。

GitHubのリポジトリ設定で Pages の公開元を **GitHub Actions** にする。Actionsで **Castle release** を開き、`main` を選んで実行する。`publish` をオンにした手動実行が検証を通過すると、プレイ版の `index.html` が公開される。レビュー用のプルリクエストと通常のマージでは検証を実行する。`publish` をオフにした手動実行でも、公開前の検証とHTML取得ができる。

初回公開後は実行結果の公開URLをiPhoneのSafariで開き、新規開始と同じURLでの再開を確認する。公開されたHTMLの `castle-revision` に入っているコミット番号と公開実行時のコミット番号を照合できる。ファイルで遊んだ試遊版と公開URLは保存先が別になる場合がある。公開URLを維持した更新では、同じ保存キーを使う。
